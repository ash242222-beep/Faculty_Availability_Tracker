Central Availability Resolution Logic

Priority Rules

The application guarantees consistent availability results through a strict single central resolver function: getFacultyAvailability(facultyId, date, time).

Priority Rule Condition Evaluation Behavior Output Status
#1 Inactive Account If faculty has is_active = false (paused by admin) Unavailable (Inactive)
#2 Temporary Override Target date & time falls within an active availability_overrides window Status from override (takes precedence over timetable)
#3 Regular Timetable Day and time matches a scheduled class in timetables In Class (Includes course & room)
#4 Current Status If querying for current time, checks latest faculty status update Available / Present / In Meeting / Unavailable
#5 Default Fallback No schedule entry or status recorded Not Updated
